# Run 002 - 2026-06-19

## Setup

- Started from the main menu after Run 001 was reset from `NGameOverScreen`.
- Run: unseeded couch co-op, 4 player slots.
- Characters: Ironclad, Silent, Defect, Necrobinder.

## Result

Unplayable roadblock on Act 1, floor 2, immediately after choosing the first monster node.

The API reported `state_type: monster` with message `Combat ended. Waiting for rewards...`, but there was no `battle`, no hand, no rewards screen, and no enabled proceed action. The game process and local endpoints remained responsive.

## Flow

- Ironclad: Chose Scroll Boxes from Neow/Ancient, entered `bundle_select`, selected bundle 1 containing Thunderclap, Tremble, and Evil Eye, then confirmed successfully.
- Silent: Intended to choose Golden Pearl by index, but the private option at that index was Arcane Scroll.
- Defect: Intended to choose Golden Pearl by index, but the private option at that index was Neow's Torment.
- Necrobinder: Intended to choose Scroll Boxes by index, but the private option at that index was Fishing Rod.

After all Neow choices resolved, slot 0's generic `proceed` returned the party to map. The same `proceed` action on the other slots then returned `No proceed button available or enabled`, because the shared transition had already happened.

The party selected the monster at `(2,1)`, which led to the stuck post-combat/pre-reward state before any combat actions were available.

## Issues And Quirks

- Run start after reset emitted several transient `state=unknown` WebSocket updates before the final map state.
- Neow/Ancient option indexes are private per slot. Choosing the same displayed index from slot 0 produced different relics for other slots, which is correct only if each phone has its own current option list and dangerous if any shared UI/action flow assumes slot 0's options.
- After bundle confirmation, all slots showed `event.can_proceed: true` with an empty `event.options` array. Slot 0 could leave via generic `proceed`, but the other slots errored once the shared transition had completed.
- The first monster node became `state_type: monster` with `Combat ended. Waiting for rewards...`, while `end_turn`, `proceed`, and `claim_reward` all failed. This halted progress without a crash.

## Recovery Tried

- Waited 5 seconds for rewards to appear; state did not change.
- Tried `end_turn`; returned `Not in combat`.
- Tried `proceed`; returned `No proceed button available or enabled`.
- Tried `claim_reward` index 0; returned `Rewards screen is not open`.
