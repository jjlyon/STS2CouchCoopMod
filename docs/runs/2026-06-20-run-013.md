# Run 013 - 2026-06-20

## Setup

- STS2 was already running with the latest installed mod.
- Run: unseeded couch co-op, 4 player slots.
- Characters: Ironclad, Silent, Defect, Necrobinder.

## Result

Unplayable roadblock on Act 1, floor 2, immediately after all four slots voted into the first monster node.

All four slots reported `state_type: monster` with `Combat ended. Waiting for rewards...`, but no battle, rewards, event, card-selection, card-reward, or map state was available. The players were all alive and no combat payload was exposed.

## Flow

The run began with an Ancient node at floor 0, which opened Neow.

- Ironclad: Chose New Leaf. A transform card-selection prompt opened; selecting Strike left the prompt visible until `confirm_selection` was sent, after which the slot returned to map.
- Silent: Chose Pomander. The upgrade card-selection prompt opened; selected Survivor. A state read immediately afterward failed with a canonical model placement error, but later recovery returned Silent to map with Pomander.
- Defect: Chose Small Capsule. A rewards state appeared with Red Mask as a claimable relic. `claim_reward` returned a blank response, and after `proceed` the slot returned to map but the player relic list still only showed Cracked Core and Small Capsule, not Red Mask.
- Necrobinder: Chose Arcane Scroll. The slot showed Neow done with `can_proceed: true` and returned to map after `proceed`.

Before the run returned to map, state was briefly inconsistent:

- Slots 1 and 3 failed state reads with `Failed to read couch state: Canonical model of type MegaCrit.Sts2.Core.Models.Cards.SwordBoomerang used in incorrect place.`
- Slot 2 reported `state_type: rewards` for Defect, but also included a stale Ironclad transform `card_select` payload.
- Slot 3 reported Neow done for Necrobinder, but also included the same stale Ironclad transform `card_select` payload.

The run recovered without restarting after sending conservative confirm/proceed/claim actions. All four slots then showed map state with the correct slot identities.

The party chose the middle first-monster path at `(3,1)`, because it led directly to an Unknown node. All four slots voted successfully, and the final response queued travel to the monster. The state then landed in the combat-ended limbo blocker rather than a live battle.

## Issues And Quirks

- Reproduced the first-combat limbo blocker again: every slot saw `state_type: monster` and `Combat ended. Waiting for rewards...` with no actionable state.
- State payloads can temporarily include another slot's card-selection prompt. In this run, Defect rewards and Necrobinder Neow-done state both included Ironclad's New Leaf transform prompt.
- Some state reads can fail during reward/card prompt cleanup with `Canonical model ... used in incorrect place`; this recovered after follow-up actions, but would be disruptive to phone clients.
- Small Capsule surfaced Red Mask as a reward, but claiming/proceeding did not leave Red Mask in Defect's visible relic list.

## Fix Validation Notes

- Multiple Neow reward grab did not reproduce.
- The run recovered from the mid-Neow state errors without restarting STS2.
- First-combat limbo did reproduce.
